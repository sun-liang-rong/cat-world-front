# 用户体验优化实施记录

日期：2026-10-10。基于工作区扫描报告及用户授权实施；设计目标是让“轻松三消→帮助猫咪→建设安家→继续闯关”更清晰。以下为实际落地范围，不代表真实玩家留存已经提高。

## 已实施

| 玩家体验 | 实现与边界 |
| --- | --- |
| 分享返回不会卡住 | 微信分享不依赖不存在的 success/fail 回调；仅记录调起/异常，不声称好友收到。取消分享不影响基本玩法，分享不发金币/复活/道具。 |
| 可选奖励可靠 | 微信与 TapTap 独立广告位/SDK；仅 isEnded=true 领奖，取消/超时/迟到回调不领奖；每次展示销毁实例，未配置微信广告位隐藏入口。预览模拟完播。 |
| 中断还能接着玩 | 本地快照覆盖棋盘/槽位/目标/道具/猫技能/试住扣次/有效耗时；背景暂停音频和有效计时；首页继续本局；终局清理快照，旧档兼容，坏主记录尝试本机冗余副本。主动离开局面会丢弃快照。 |
| 对局反馈公平 | 骰子先验证当前槽位＋新棋盘的可解性，限次搜索未找到结果不扣库存；锤子和猫技能保护必需目标牌，复活把必需目标牌放回棋盘。未承诺任何局面经复活都可解。 |
| 快速点击稳定 | 飞行计数在入槽时归零，不依赖可被重排取消的落地 tween 回调；空棋盘即结算，不另要求槽位清空。复活重新启用道具按钮。 |
| 前五关平滑 | 牌量 18/27/33/42/48，种类 4/4/5/6/6，保留多层遮挡与可解性校验；模拟失败率目标 0–15%，不是玩家实测。 |
| 首只猫更早安家 | 大橘在小屋清理 5 格后永久加入，无装备时自动上阵；新试住为 5 局有效主线，旧剩余次数保留；不重置建设和其他猫。 |
| 猫技能不挡牌 | 技能入口固定在顶部标题与设置之间，88×88 热区，显示充能/可发动/已使用/试住状态；移除棋盘悬浮与拖动，旧位置存档保留但不使用。预览发现旧浮窗完全遮住右上角末牌，源码修复与类型检查完成，待编辑器重新导入后验证新布局。 |
| 猫帮助更常见 | 充能满后手动使用，每局一次，无分钟冷却；未消耗充能跨局保留。猫详情两行技能说明，成长只突出下一里程碑；互动记录独立于金币升级，好感 20 解锁照片。 |
| 继续玩的目标清晰 | 下一关/重试为大主按钮，视频奖励和返回为次操作；首页一个当前目标、实际入住/试住猫；未解锁模式隐藏，挑战强提示推迟到第 11 关起；关闭建设引导不反复弹出。 |
| 小镇有可见变化 | 每个建设小格添花，跨阶段保留；小屋清理完成有安家文案。复用既有素材，不新增 AI 美术。 |
| 回访与长线目标 | 首页露出可领取七日旅程奖励；过期活动隐藏，有可领取内容才亮提示；120/140/160 关解锁相册故事，好感照片复用已有图片。 |
| 加载与内存更稳定 | 图片/Bundle 等待 20 秒上限，挑战生成 15 秒上限；首屏失败提供重试/先进入首页；同路径纹理缓存复用，避免反复重建。缓存仍常驻，没有 GPU 淘汰/真机峰值结论。 |
| 微信榜符合数据边界 | 仅累计星星写微信云 KV，好友数据只在开放数据域读取；其他纪录只留本机；预览 Mock。新增构建后准备脚本登记开放数据域和缩短网络超时。 |
| 优化效果可观察 | 事件目录 v2、逐事件属性白名单、独立本机匿名 ID，新增恢复/技能/每日补给事件；后端与看板新增首次启动分群、主线达成率、D1/D3/D7，自然日观察未满为 null。没有上传 PlayerState。 |

## 验证证据

- Cocos Creator 3.8.8 自带 TypeScript 全客户端检查通过；编辑器预览已验证首页、商店、每日任务、猫咪详情、结算等页面；独立 Cocos web-mobile 构建成功，客户端 TypeScript 检查无报错。
- 1000 个关卡种子通过：唯一性、合法布局、见证路径、Solver 可解性、难度恢复与救援；无尽补波检查通过。
- PlayerStore 验收通过：默认值、奖励、建设/猫解锁、商店、任务、试住、旧档归一化、本地冗余恢复、合法/非法快照、空棋盘终局快照、试住与难度上报标记。
- 平台回归通过：微信分享无回调、SDK 缺失/空广告位、视频取消/完播/超时、旧实例迟到回调、销毁。
- GameScreen 实际逻辑回归通过：取消落地 tween 后飞行计数不遗失、快速连续入槽、空棋盘结算、复活重启道具、收集目标保护。只模拟 Cocos 渲染层，不读取或修改真实玩家存档。
- 事件契约 v2（47 个事件）同步检查通过；NestJS 6 套测试共 29 项通过并成功构建；Vue 看板类型检查与生产构建通过。
- 微信构建后脚本在临时构建夹具验证通过：保留既有配置、复制开放数据域、登记路径与超时。
- 编辑器预览使用既有测试存档：完整打通第 2 关，中途刷新→继续本局恢复原棋盘与槽位→通关→进入第 3 关；第 3 关终局刷新恢复后推进到第 4 关。第 4 关在快速点击下持续三消，满槽弹失败窗口、免费复活恢复操作；新版首页和猫详情说明/成长区实测可读。
- 本轮浏览器补验：第 4 关重试后快速连续三消→满槽失败→免费复活→移开旧悬浮猫查看末牌→继续三消→通关结算→点击下一关进入第 5 关，流程完整。胜利截图 `04-通关结算.png`。该截图来自编辑器已有导入版本，不代表最终技能入口布局已验收。
- 最后发现的“复活重新启用道具”修复已通过实际 GameScreen 逻辑测试，最后一轮编辑器导入/点击验收被 Mac 锁屏中断，用户回复已解锁后，桌面控制工具仍持续报告 Mac 锁屏，无法重新导入；浏览器独立可用，故仅补验上述流程。需恢复桌面连接后续验。猫详情面板为避免挡住金币 HUD 最后下移 35 设计像素，类型检查通过，待同轮复核。

## 发布前配置与平台验收

1. 配置真实微信广告位 `Main.rewardedAdUnitId`；空值有意隐藏微信视频入口，预览完播不代表微信广告已验收。
2. Cocos 用当前源码重新构建微信小游戏，运行 `node scripts/prepare-wechatgame.js <输出目录>`。本轮未重新生成正式微信包，未上传、未发布，历史 build 不算当前验收。
3. 微信开发者工具与真机验证好友榜读写/分页、胶囊安全区、小屏布局、弱网/CDN恢复、前后台/进程回收、广告取消/无填充/完播及长局内存。首屏重试是代码支持，尚未做真实断网注入验收。
4. 先同步发布 service 事件目录 v2，再发布客户端与看板。预览曾收到旧服务拒收新增 `level_resume` 的日志，本地契约检查通过，但线上服务未在本轮部署。
5. 分群 SQL 已做单元测试，尚未对正式 MySQL 做集成/索引性能验收。匿名统计 ID 迁移、清缓存、重装会影响新用户口径，不能与旧账号 ID直接关联比较。
6. `../需求.md` 已同步现行规则，但工作区根不是 Git 仓库，该文档不在三个代码仓库的提交内。

## 仍需玩家数据或后续产品设计的建议

本轮未新增个性家具选择、专属分享插图、活动运营档期、挑战金币经济调整、统一真实安全区适配或 GPU 淘汰策略。第 3 关首次免费撤回教学尚未专门制作。挑战 3000 金币是否调整须结合参与/消耗数据；后 60 关的扩展先以故事和相册实现，没有新增猫/建筑。10–20 位新玩家观察与版本分组实验须真实招募后执行，不以自动关卡模拟替代。

建议下一步先完成微信真机验收，再用真实试玩回答三个问题：首猫是否顺利安家、失败救援是否可理解、次日是否有明确回访理由。
